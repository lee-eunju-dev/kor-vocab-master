# 초등 어휘 등급 추가

## 배경

`PRODUCT.md`가 이번에 주 사용자를 "국어 학습에 흥미가 없는 중학생"에서 "초등 고학년(4학년
이상)~고등학생"으로 넓혔다. 실사용(개발자의 자녀)에서 중등 어휘가 어렵다는 피드백이 나왔고,
초등 4학년 이상 수준의 필수 어휘 등급을 새로 추가해 그 학생이 더 쉬운 단계부터 시작할 수 있게
하는 것이 이번 스펙의 목적이다.

지금 앱은 어휘 등급이 "중등 필수"/"고등 필수" 두 가지뿐이다(`lib/quiz-types.ts`의
`Grade = "middle" | "high"`). 등급 선택 화면(홈)에서 등급 카드를 고르면 그 등급의 단원 목록으로
들어가고, 단원 안의 Stage(10문제 단위)를 순서대로 깨는 구조는 이미 1차 스펙에서 확정되어 있다.
이번 스펙은 그 구조에 "초등 필수" 등급을 하나 더 추가하는 것만 다룬다.

## 사용자에게 보이는 결과

- 등급 선택 화면(홈)에 "초등 필수" 카드가 "중등 필수" 카드보다 앞에 나온다.
- "초등 필수"를 고르면 지금의 중등·고등과 똑같은 화면 구조(단원 목록 → Stage 지도 → 퀴즈)로
  들어가 똑같은 방식으로 플레이할 수 있다.
- 초등 어휘도 중등·고등과 같은 방식(Stage당 10문제, 오답도 계속 진행, 클리어 시 별점과 츄 보상)
  으로 동작한다.
- 초등 어휘 콘텐츠는 초등학교 4학년 이상 수준의 국어 필수 어휘로 채운다.
- 학생은 초등 필수를 먼저 끝까지 깨지 않아도 중등·고등 카드를 눌러 들어갈 수 있다(등급 카드
  자체의 진입은 항상 열려 있다). 다만 각 등급 "안에서" 단원이 차례로 열리는 순차 진행 방식은
  지금과 동일하게 유지된다.

## 승인된 범위

1. `lib/quiz-types.ts`의 `Grade`에 `"elementary"`를 추가하고, `GRADE_LABEL`에 "초등 필수" 표시를
   더한다.
2. `data/vocab/elementary-words.ts` 신설. 지금의 `middle-words.ts`/`high-words.ts`와 같은
   `ChapterSource[]` 형태로, 초등학교 4학년 이상 수준 어휘를 주제별 단원으로 묶어 채운다. 챕터
   id는 지금까지 쓰인 적 없는 19번부터 이어서 부여한다(중등 1~9, 고등 10~18).
3. `data/vocab-stages.ts`의 `CHAPTER_SOURCES`에서 초등 챕터를 배열 맨 앞에 둔다
   (`[...ELEMENTARY_CHAPTERS, ...MIDDLE_CHAPTERS, ...HIGH_CHAPTERS]`). 등급 선택 화면의
   `GRADE_ORDER`도 `["elementary", "middle", "high"]` 순서로 맞춘다.
4. `lib/progress-storage.ts`의 `STORAGE_KEY` 버전을 올려(v5 → v6) 기존 진행 기록을 새로 시작한다.
5. 등급 선택 화면(홈)의 초등 카드에 쓸 마스코트 표정·톤을 정해 반영한다(구체 값은 구현 시 정함).

## 관찰 가능한 인수 기준

- 등급 선택 화면(홈)에 "초등 필수" 카드가 보이고, 카드 순서는 위에서부터 초등 → 중등 → 고등이다.
- "초등 필수" 카드를 누르면 단원 목록 화면으로 들어가고, 단원을 고르면 Stage 지도가 나오며, Stage를
  선택하면 10문제짜리 퀴즈가 시작된다. 오답을 골라도 해설을 보여주고 계속 진행하며, 10문제를 다
  풀면 Stage가 클리어되고 별점·츄를 받는다 — 지금 중등·고등과 동일한 흐름이다.
- 초등 필수 단원의 첫 Stage는 처음부터 잠겨 있지 않고 바로 풀 수 있다.
- 중등 필수 카드를 누르면 지금처럼 바로 단원 목록으로 들어간다(초등을 다 깰 때까지 카드 자체가
  막히지 않는다).
- 앱을 새로고침하거나 재실행해도 초등 어휘의 클리어 기록과 별점이 그대로 유지된다.
- 브라우저를 새로고침해도 기존에 중등·고등에서 쌓아 둔 진행 기록은 이번 등급 추가로 인해 한 번
  초기화된 뒤에는(v6 이후) 정상적으로 유지된다.

## 확정된 제약과 근거

- 초등 챕터를 `CHAPTER_SOURCES` 배열의 맨 앞에 둔다. `data/vocab-stages.ts`의 기존 구현은 모든
  등급의 Stage를 하나의 전역 순서로 이어 붙여 각 등급의 "첫 단원"이 바로 앞 등급의 마지막 Stage를
  깼는지로 잠금이 걸리게 되어 있다(지금도 고등 첫 단원은 중등을 다 깨야 열린다). 초등 → 중등 →
  고등 순서로 자연스럽게 이어지는 난이도 흐름을 만들기 위해 초등을 맨 앞에 두기로 했다.
- 위 배치의 부작용으로 중등 첫 단원의 잠금 조건이 바뀌므로, `STORAGE_KEY` 버전을 올려 진행 기록을
  새로 시작한다. `data/vocab-stages.ts`에 이미 "어휘를 대량으로 채워 넣을 때는 STORAGE_KEY 버전을
  올려 기록을 새로 시작하는 편이 안전하다"는 관례가 문서화되어 있고, 진행 기록은 기기 로컬에만
  저장되는 개인 기록(현재 사용자는 한 명)이라 초기화의 실질적 비용이 낮다고 판단했다. 등급끼리
  잠금을 완전히 분리하는 리팩터링(각 등급 첫 단원을 항상 열어 두기)도 검토했지만, 이번 스펙의
  범위를 넘어서는 구조 변경이라 채택하지 않았다.
- 등급 "카드" 자체의 진입은 지금처럼 항상 열려 있다(1차 스펙 이후 바뀐 적 없는 동작). 이번 스펙이
  건드리는 것은 각 등급 "안에서" 단원이 차례로 열리는 순차 진행 로직뿐이다.
- 단어 선정은 `PRODUCT.md`가 정한 대로 별도 분석 없이 기존에 정리된 초등(4학년 이상) 필수 국어
  어휘 목록을 활용한다. 구체적으로 어떤 자료를 기준으로 삼을지는 미룬 점에 남긴다.
- Stage·퀴즈·보상 로직(문제 10개, 오답도 진행, 별점·츄 보상)은 전혀 바꾸지 않는다. 등급이 하나
  늘어나는 것은 기존 챕터·Stage 자동 생성 로직(`data/vocab-stages.ts`)이 그대로 처리한다.
- 오답 보기(4지선다 중 정답이 아닌 3개)는 지금처럼 등급 구분 없이 전체 어휘(`ALL_WORDS`)에서
  뽑는다. 그래서 초등 문제에 중등·고등 어휘의 뜻풀이가 오답으로 섞여 나올 수 있는데, 이를 등급별로
  분리하지 않기로 했다. 오답이 명백히 어려운 말이면 오히려 정답을 더 쉽게 찾을 수 있고, 초등 어휘가
  처음엔 최소 1개 단원(10단어)뿐이라 등급 안으로만 제한하면 오답 보기가 부족해지거나 반복될 위험이
  더 크다고 판단했다.

## 가정 (뒤집기 쉬운 선택, 필요 시 조정)

- 초등 카드의 마스코트 표정·톤은 구현 시 자유롭게 정한다(예: 중등과 다른 톤을 써서 세 등급이
  시각적으로 구분되게 하는 정도).
- 초등 챕터의 단원 이름·주제 구성은 중등(`표현과 문학`, `생각과 논리` 등 5개 세부 주제 × 10단어)과
  같은 형식을 따르되, 구체적 주제 이름은 실제로 단어를 채우면서 정한다.
- 초등 챕터 수·전체 단어 수는 처음부터 중등(9개 단원)만큼 채울 필요는 없다. 최소 1개 단원(10단어)
  을 먼저 채워 화면에 붙여 보고 정상 동작을 확인한 뒤, 이어서 단원을 늘려 가는 순서를 권장한다.

## 범위 밖

- 캐릭터 도감·상점(`docs/specs/creature-collection`)과의 연동 — 별개 스펙이고, 이번 등급 추가와
  독립적으로 진행된다.
- 등급별로 순차 잠금을 완전히 분리하는 구조 변경 — 진행 기록 초기화로 대신하기로 했으므로 이번
  스펙에서는 하지 않는다.
- 학년(예: 초등 4학년/5학년/6학년) 단위의 세분화된 등급 — "초등 필수" 한 단계로 시작하고, 필요성이
  확인되면 이후 스펙에서 검토한다.

## 미룬 점

- 초등 어휘의 구체적 출처(교과서 어휘, 국립국어원 등급 자료 등 초4 이상 기준으로 삼을 목록)는
  아직 정하지 않았다. `PRODUCT.md`에도 같은 내용이 가정으로 남아 있다. 구현 시작 시 중등·고등
  어휘를 고를 때와 같은 방식(별도 분석 없이 기존 목록 활용)으로 정한다.
- 초등 챕터의 실제 단어·뜻풀이 콘텐츠는 이 스펙에 포함되지 않는다. 화면·로직 요건만 정했고, 실제
  단어 채우기는 별도 구현 세션에서 진행한다.

## 남은 위험

- 진행 기록 초기화(`STORAGE_KEY` v5 → v6)는 이번 등급 추가뿐 아니라 이미 저장된 모든 등급의 클리어
  기록·별점을 한 번에 지운다. 사용자가 이미 확인하고 권장안으로 선택했지만, 배포 시점에 실사용자
  (자녀)에게 "한 번은 처음부터 다시 시작한다"는 점을 미리 알려 주는 편이 좋다.
